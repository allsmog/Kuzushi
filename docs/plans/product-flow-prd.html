Product Requirements · local-first security workbench

A control room for non-deterministic scans.

An LLM security scan is stochastic and costs money every run. Kuzushi makes it governable — a control plane to steer it, a visual plane to see it.

status proposal — awaiting review grounded in cannon · defending-code · AIxCC · IRIS · OSS-Fuzz-Gen
The promise
Point Kuzushi at a target, aim it, and fire controlled sweeps of AI scans you can steer, price, corroborate, and see — until you have confirmed, evidence-backed findings you can defend.
01

The load-bearing idea

The same agent, pointed at the same code, surfaces different findings run to run — and each run spends tokens. That non-determinism isn’t a bug to fix; it’s the material the product is made of. Anthropic’s own reference harness says it plainly, and its entire design is two countermeasures:

why this product exists

Any single AI scan is flaky and noisy. The countermeasures are union across a permuted sweep (coverage from variance) and a separate adversarial verifier whose only job is to disprove findings (precision). Everything else — the ledger, the cockpit, seeding — is lifecycle management around those two.

Sample

Fire a sweep — focus × strategy × model × runs — and union + dedupe the results. Coverage comes from variance, not one lucky pull.

Corroborate

A guilty-until-proven-innocent verifier, multi-vote and blind, ideally crash/PoV-backed. In the reference harness this roughly halved false positives; a required PoC drove them near zero.

Discovery is easy to parallelize; the bottleneck has moved to verification, triage, and patching. A product that just fires more agents makes more noise. The value is the loop that turns noisy, stochastic, expensive output into a small set of corroborated, proven findings — without clobbering the human’s judgment. Both mechanisms must be operator-controllable, not buried. That control — plus the visibility to see the invisible agent reasoning — is the whole product.

02

The problem: the parts, but no control room

Kuzushi works, and most of the machinery is real. The failure is that it presents the parts but not the room that lets you govern a non-deterministic scan. Each symptom is traceable to an audit or the current-state map.

A

You can’t steer where the non-determinism spends.

Phase execution is a static 22-entry PlanningTaskId walker — not a signal-driven, priced sweep. No focus × strategy × model × runs matrix, no queue of proposals you approve under a budget. The COVERAGE MATRIX is display-only.

B

You can’t shape the scan — the harness is frozen.

Engine wiring, detector set, and tool graph are compile-time. Prompt text is editable, but you can’t mutate the harness — seed it from recon, retarget it by typing “focus on SQLi”, or let coverage feedback evolve it.

C

Engines you own aren’t controllable per-scan.

12 MCP oracles, cpg:build, codeql-db:build — but enablement is artifact-presence-gated behind the scenes, never an explicit, cost-estimated toggle. No way to say “turn on Joern + CodeQL for this confirm pass” and see the cost.

D

The two planes are conflated.

A deterministic seed (Semgrep/CodeQL/SARIF) and a non-deterministic hunt are different evidence that should corroborate one row. The ledger already merges them — but nothing lets you ingest an external SARIF/Semgrep file, and nothing steers the two planes.

E

You can’t compose or save a strategy.

No named, replayable recipe (deep = pattern + iris-taint + review×2 + invariant). The parts exist — variant, ndiff, overrides, phases — but don’t compose into a stored strategy object.

F

You can’t fully trust or see the output.

Confirmed-vs-guess is detail-only; a canceled task can flip to ✓ done; the Workbench fabricates a phase chip with no target and tracks the viewed page, not reality; the DAG legend names a state rows can’t show.

Plus the standing friction: an inventory-shaped surface (42 modules / ~67 tools), a keyless first run that hits an auth wall before any finding, token waste from duplicate triage, CI-blocking headless edges (recon:import unreachable, --target three ways), and detection quality that’s a claim (baseline.json = {}) not a number.

Composable parts → strategies

The 42 modules aren’t a catalog to shop. They’re parts of four kinds, composed into strategies and fired as sweeps.

KindParts (examples)Role in a scan
Detectorssemgrep · codeql · static_review · secrets · dynamic/fuzzturn a target into candidate findings
Analysis oraclestree-sitter · Joern CPG · CodeQL · clangd LSP · entry-points · (KLEE)answer reachability / callers / taint-path deterministically
Signal generatorscommit-archaeology · threat-model · dep-intel · evolution · fuzz-reconpropose priced sweeps from evidence about the target
Verifiersmulti-lens vote · metamorphic · PoV/crashtry to disprove; promote proof state

A strategy is a named, saveable, replayable recipe that composes parts — the sweep’s “variant” axis:

# engagement/strategies/*.toml
deep      = pattern(semgrep+codeql) + iris-taint(CPG) + review×2 + invariant-check
quick     = secrets + static_review×1
pr-review = diff-scope + review + reachability-vote      # Full vs Delta mode

Diversity + merge beats one pipeline — every AIxCC winner runs many diverse engines in parallel and funnels into one dedup/score gate (theori merges five vuln sources; atlantis ensembles input-generators and three diverse patch agents). Strategies make that composition an operator-owned object.

06

The harness — the mutable unit of a scan

“The harness” is the whole configuration of a non-deterministic scan, modeled as one versioned, editable artifact — not scattered flags.

harness = {
  focus_areas[]     # ranked {entry(file:function:line), input_surface, rank}
  strategy          # the composed recipe
  engines_enabled   # cpg? codeql-db? which MCP oracles? clangd LSP?
  model_tiers       # {find: mid, triage: cheap, verify: deep, patch: deep}
  runs / variants   # the sampling matrix
  oracle            # ASan crash | asserted invariant | reachability
  seeds[]           # corpus seeds / operator hunches / imported findings
  budget            # cap + priced proposals
}

Three ways it mutates — this is the differentiator:

  1. Recon seeds it. A discover pass clusters attacker-reachable code into ranked focus areas, detects the toolchain/build system, and extracts an input vocabulary — pre-populating a partitioned plan. A fuzzer is never handed main().
  2. The operator edits it — by typing intent. “Focus on SQLi” is a first-class steering input that re-ranks focus areas, sets the oracle’s CWEs, and biases seeds. (This is the knob the fuzz-plugin sources lack and the reference harness only gestures at.) You can also hand-edit the harness or attach a design doc as provenance-tagged <untrusted-source> evidence.
  3. Feedback mutates it dynamically. Reachability prunes unreachable candidates. An LLM-authored fuzz harness runs a build-and-fix loop (compiler rejects → LLM fixes); coverage (cov:/ft:/NEW) decides extend-vs-stop; an escalation ladder pushes a clean crash toward a controllable OOB write. Only a reproducing PoV promotes a finding to proven — the OSS-Fuzz-Gen / Big Sleep mechanic, productized.

09

The signifier & trust contract

Because the promise is governed evidence, the finding surface has a hard, release-gating contract. Confirmed-vs-guess is visible in every list:

✓ confirmed · path/PoV ◇ candidate · linked ? unverified ! rejected
  • Each finding shows its evidence tier, the oracle that produced it (structural / tree-sitter / Joern / CodeQL / PoV), its corroboration count, and its vote breakdown.
  • Cost and corroboration are always on screen during a run — the operator never spends blind.
  • The phase chip/rail reflects engagement reality, never the viewed page, and never renders without a target.
  • A terminal state is terminal: canceled never becomes done.
  • Verification independence is a visible badge — the verifier saw only the evidence (PoC/path), not the finder’s reasoning (the two-container trust boundary).

A change that regresses this contract is a release blocker.
