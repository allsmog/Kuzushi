Setup now offers `Import context document` in the Map plan. This replaces the
typed module/options/run sequence required by J161 with a visible task and its
declared Path editor. The existing Rust import executor and prepared dispatch

## Product behavior and contracts

The new `PlanningTaskId::ImportThreatModel` belongs to Map, depends on repository
context and is an action rather than a cache of the active compatibility mirror.
The actual planning runner consumes this dependency order. Import is excluded
from deterministic and model-recommended preselection, including failed history.
Selecting it remains an explicit operator choice.

The plan presets the existing `activate` option to false. Operator edits retain
control of that option. Setup's Context import row opens the descriptor's Path
option and preserves the plan and composer. Missing source blocks both Start
Map and direct planning confirmation before queueing work. Runtime-free import
does not require a model or credential. Import and model-backed generation need
separate Map reviews, so one cannot silently replace the other's context.

Source selection is shared with the core executor. A non-null inline document
retains its existing precedence; null falls back to a non-empty trimmed Path.
Preflight checks source presence without opening the document. Actual execution
retains the existing 16 MiB bounded file read, JSON parsing, normalization,
source binding, grounding and immutable persistence. Setup explicitly discloses
that those checks run during import. A ready input is not a verified document.
The source selector and its validation helper have no IO or model effects.

The Map planner now identifies missing document input and calls executable
actions fresh actions. File attachment no longer passes through a nonexistent
tool's option validation. It remains a local inline action. Existing skip/run,
option editing and compatibility tool behavior are retained.
