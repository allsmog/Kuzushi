# Explicit supporting files for standard Review

The separately approved source-input Review cited the supplied route but still
needed the service, store and authorization policy. This increment lets an
operator choose supporting files explicitly, inspect their frozen text and
omissions, and prepare another finite job. It starts no new live-model work.
Thirteen cumulative experiment requests remain recorded, with no capacity left.

## Behavior

`sourceEvidenceFiles` is declared on `triage:run` and consumed through shared
prepared dispatch. It accepts at most 16 exact normalized repository-relative
paths under the explicit standard/cited policy. It expands no dependencies or
globs and creates no follow-up jobs. Duplicate, absolute, traversal, control-byte
and non-normalized selections fail before preparation.

Primary and supporting code share the existing 32 KiB default, 256 KiB maximum
raw-source allowance across the entire batch. Capture follows observation order,
then file selection order. Supporting files repeated for multiple observations
count each time because each Review request receives that input. A selected
primary path is included once for its observation. Missing, excluded, binary
and over-limit files remain omissions. Source snapshots must authenticate the
observation; a different or unavailable recorded tree receives no supporting code.

Nonempty selections create immutable evidence version 2, with supporting-file
receipts on each eligible observation. Empty selections preserve version 1 and
its original prompt block. Reading authenticates target, generations, source
snapshot, selected path order, file hashes and byte counts. Current source drift
blocks new approval and execution; historical readers retain frozen bytes.
Every admitted vote receives the selected code through the canonical untrusted
repository wrapper in the full prompt template. Original discovery messages
remain intact. Matching code does not determine the finding's verdict.

## Operator controls

`f` opens a bounded fuzzy file picker from the Review form or source reader.
Space toggles a file, Tab switches between repository search and the selection
basket, Enter applies, and Esc cancels. Search queries and cursor positions
survive basket navigation; asynchronous index updates retain selected files.
Capture-order numbers distinguish the selected order from sorted search results.
An exact pasted path can be chosen when it is absent from the bounded index;
preparation validates it against the source tree.

Cancel preserves the Review draft. Apply invalidates the old evidence reference
and fixed plan only when choices change. Source policy `none` clears the choices
explicitly. Selection and preparation grant no allowance and start no worker.
The full-frame picker retains visible controls in the six-size terminal matrix;
plain output uses the same Review selection semantics rather than attachment
instructions. The source reader displays each selected file and omission with
numbered lines, alongside raw and formatted input sizes.

The frozen-source reader also owns keyboard input. A regression reproduced
Enter emitting one approval-dispatch effect while the operator was reading.
The reader now ignores Enter and hidden planner shortcuts for draft reset,
strategy, context, model and call limits. Its displayed paging, file picker,
input view and back controls remain active. `v` returns to the plan for any
approval or other edit. This preserves explicit spending decisions.
