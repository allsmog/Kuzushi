# Operational module audit, October 8, 2026

The audit found supported-path defects in tracking and reporting, rather than
evidence for deleting implementations. Campaign status and coverage runs could
displace a scan as the source of an implicit report. Status also failed canonical
run persistence when projected historical spending was unresolved. Registration
and a successful inner JSON result had concealed that failure.

## Roles and curation

Campaign now supports different discovery tiers per tool. The optional
`discoveryMaturity` descriptor restricts a Core owner; it cannot promote a Labs
or Compatibility module. Shared default catalogs and guided capability actions
use the effective tier, while `--all` and exact dispatch preserve compatibility.
The same metadata survives the approved local KWP worker boundary. Its host test
explicitly records that both tool tiers executed through prepared dispatch.

`campaign:study` remains the supported accepted-scope planner.
`campaign:plan` and `campaign:coverage` become Compatibility actions because
their shard/threat format does not consume accepted scope studies. Status remains
Core as an operational tracker and retains its disclosed trend-history write.
Status and coverage use Operate, so neither becomes Map evidence or an implicit
analysis source. Operational classification admits workspace/target operations;
repository execution and external actions remain unclassified in that phase.

The current catalog contains 109 visible tools across all tiers and 100 default
tools. Every row of `bounded-investigation-tools.json` now has all nine audit
dimensions, refreshed descriptor facts and a separate owner tier. Missing outcome
evidence remains explicitly pending. The retirement list is empty.

## Historical progress and spending

The legacy fold admits only known Scan jobs with a shard binding. Preparation,
unclassified jobs and modern non-shard studies are counted as excluded. Empty
matrices no longer invent a column. Tool JSON and the TUI distinguish historical
job progress from repository coverage and current-source applicability. Accepted
scope studies use their investigation Report.

Status preserves historical spending in its existing payload. Shared dispatch
binds `dataCostScope: projection` from a runtime-free descriptor and strips any
module-supplied marker. Current execution cost is read from envelope fields in
that case. It is unavailable when unmetered; old spending cannot become the cost
of a new status read. Model-backed descriptors cannot declare a projection.
The KWP host explicitly rejects this declaration. Its worker sanitizer retains
broker-owned current cost and strips module-supplied monetary claims. A failed
projection experiment demonstrated that boundary; the protection is unchanged.
