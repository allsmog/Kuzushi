# Finite job reading and inspection

October 14, 2026. Local changes on main at `f8649511f746`.

The previous native scope-editing journey exposed a twelve-job plan as opaque
job ids with inclusion checkmarks. Fixed studies cannot change inclusion there,
and the visible Enter inspection hint only reopened the job list. These choices
made it harder to connect approved work with source boundaries and outcomes.

The shared campaign snapshot now derives optional human labels from recorded
scope/context cases and valid pass numbers. Single-condition batches show their
recorded pass count. Missing, malformed or legacy metadata retains the job id
without inventing case or pass facts. Labels do not replace dispatch identity,
change state, edit a plan or grant approval. The status tool exposes the same
optional labels through prepared dispatch. Diagnostic projections are bounded
and escape terminal controls without rewriting stored queue or run artifacts.

The TUI's fixed job list shows those names, execution state and attempts. Enter
opens one job's recorded scope/context references, explicit omissions, model
selection, engine choices, attempts, outcome, finding count, cost and run id.
Unknown cost remains unknown. Current settings never fill historical omissions.
The reader does not claim that merely displaying a reference authenticates its
current source or shows its complete text; a separate plan/allowance action reads
the frozen source and context receipts before execution.

q restores the selected job in the list. Up/Down inspects adjacent jobs and
resets their reading position. Paging and resize use the existing document
reader. The composer remains owned by its existing input mode. Active inspection
keeps cancellation visible, including pending Stop state. Reading starts no
jobs, requests, scans or new allowance.
