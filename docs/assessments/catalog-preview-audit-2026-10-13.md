# Catalog preview, honest outcomes and startup

`threat-intel:apply` answers which recorded catalog entries can be routed to
existing tools and which remain unsupported. Its default dry run previews
metadata, without querying a model, inspecting source or starting hunts.
It is a Labs action outside the accepted scope-study workflow. Exact dispatch
and the existing live option remain available; no implementation is retired.

Four prepared-dispatch tests initially failed: the descriptor required a runtime
even for dry planning and allowed this supporting result to own Map progress.
Runtime preparation and execution now share one canonical `dryRun` predicate.
The default is still true. Explicit false still requires a runtime/model and
approved accounting; absence cannot silently turn live work into a preview.
The result is auxiliary Map and cannot complete that phase.

Four further tests reproduced false completion when injected child receipts
were failed or partial. These tests run no hunt, provider or target code.
The parent now retains child envelopes and observations, reports failed when
child failures leave no completed/partial work, and reports partial for mixed or
partial outcomes. Skipped children are not counted as dispatched work.
Additive `planned`, `dispatchRequests` and `partial` counts distinguish preview
from invocation. The legacy dry-run `dispatched` count remains for compatibility.

Startup classification previously used only a tool's phase label. It now also
checks whether that descriptor can own a phase result. A complete small history
of auxiliary receipts alone does not establish an engagement. Existing source
artifacts and findings still provide independent resume signals. Primary or
unknown runs, malformed/cold history and prefixes exceeding the 32-record
inspection limit retain conservative resume behavior. No index is repaired or
history rewritten by this classification. The displayed action is now
**Catalog dispatch**, replacing the misleading invariants label.
