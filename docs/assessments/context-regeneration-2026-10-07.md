# Selected context regeneration

The context editor now offers `g` to propose replacement text for the selected
explanatory field. Human edits must be saved or explicitly discarded first.
`G` opens multiline guidance, `M` opens model choice, and the existing allowance
review approves one fixed context job, one worker and one attempt. Preparing and
approving the plan start no work. A separate launch runs the job.

The shared `threat-model:regenerate` descriptor supports one to eight editable
pointers. Its executor authenticates the exact parent and recorded source,
supplies bounded architecture and source excerpts, and makes one logical
synthesis request with tools disabled. Transport retries use shared durable
admission. There is no delegation, output repair loop, scanner or finding
verdict. Malformed, partial, protected or mismatched edits publish no copy.

A successful result creates an inactive lineage. It preserves unselected human
text, evidence, source scope, original objects and the globally active context.
It clears the old verification stamp and records the parent, fields, model,
run, prompt digest, supplied excerpts and omissions in a versioned regeneration
receipt. Source is checked before the request, after store-lock waiting and
after publication. Final drift retains a historical partial result rather than
claiming a current context. Recovery validates the parent, model, run and field
set against the frozen job and authenticates the immutable object.

The chooser's `d` comparison reads the exact parent locally. Actual before/after
text leads the view; revision IDs remain available below it. Paging, failed
parent reads and local retry preserve the inspected candidate. Selecting it
with `a` binds a new study draft without accepting work or changing global
context. Model-picker cancel restores the precise generation form. An explicit
model change invalidates the plan while preserving guidance, parent selection,
saved results and spending history.
