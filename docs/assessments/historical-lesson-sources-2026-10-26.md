# Historical supporting source for lesson generation

The earlier lesson generator supplied only the cited observation file. A
cross-file review principle could therefore lack its service, policy or storage
context. The operator could give guidance but could not select supporting
historical source through the lesson planner.

## Implemented draft

The descriptor now declares `sourceEvidenceFiles` and `sourceEvidenceRef`.
Selections use the same exact-path validation as standard Review, with at most
16 paths and no dependency expansion. Cited source is first; supporting source
uses the remaining `maxSourceBytes` allowance in the selected order. The cited
file is not included again as supporting source.

All source comes from retained observation-time content. The reader uses the
exact observation and snapshot, authenticated tree membership and bounded
content-store reads. It does not open the current source files. A changed or
deleted checkout therefore cannot replace historical bytes. A missing tree or
blob remains an omission. Some older observations retained only a cited file;
their supporting membership stays unavailable.

Preparation retains a `lesson-source:` bundle with the origin, selection, byte
limit, source text and omissions. Approval and execution recheck that bundle.
Changing order, files, origin or the limit requires another plan. The optional
bundle reference remains in the saved generation receipt. Inputs without
supporting files preserve the original prompt shape and receipt serialization.

Before preparation, `f` opens the shared file basket. The picker identifies its
current path list as a browsing aid and accepts an absent exact historical path.
After preparation, `v` opens a read-only source document. It presents each file,
included bytes, historical text and omissions. Enter and planner shortcuts do
not execute work from that reader; Esc restores the previous plan position.
The real generator still produces only a draft. Human review and context reuse
remain separate actions.

## Remaining limits

Source completeness depends on what the original observation retained. The
current file index does not enumerate deleted historical paths; the operator
must enter an absent path exactly. A missing captured blob is never recreated
from a later checkout. Corrupt retained content fails before a provider request.

The tests qualify bounded source plumbing and input ownership. They do not
establish lesson usefulness across unfamiliar repositories, broad context
quality or operator acceptance of the terminal experience.
