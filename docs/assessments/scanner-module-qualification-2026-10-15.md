# Offline scanner and module qualification

Scripted runtime fixtures now supply finite allowances through the real ledger.
Each query, triage request and tool-loop turn reserves before execution and
settles the returned cost report.
Failures leave unresolved reservations, unknown cost stays unknown, and extra
requests fail before reaching the inner runtime. The shared test adapter forwards
preflight checks, tool support and scope authorization rather than manufacturing
permission. Callers supply inert runtimes, and the adapter is compiled only for
tests.

The restored cases cover context enrichment, selected source scanners,
classification, vendor assessment and plugin-backed source analysis. The three
scripted systems-analysis stages have an explicit three-call allowance. A
missing plugin dependency and an unsupported scoped runtime still fail
actionably without consuming a query. Selected-scope discovery retains rejected
out-of-scope observations in its receipt and persists only the selected finding.
The compatibility alias correctly reports partial, unverified source coverage.

Thirteen further module fixtures now reach their intended executors with exact
scripted request allowances. They cover single-shot triage, source-reading audit
turns, discovery followed by review, source-only engine routing and static tool
policies. Assertions check committed and unresolved reservations in addition to
persisted findings and evidence. A failed audit retains its inserted finding,
records the failed request and creates no triage decision. The targeted model
override is approved explicitly by the fixture; another model remains refused.
No production allowance or dispatch rule was relaxed.

Seven older terminal-worker failures are also cleared. Six model-backed cases
now share an owned fixture whose bridges live outside scanned source and use
the real framed request-admission protocol. Each fixed script runs only after
reservation, returns an explicitly nonbillable fixture result and settles its
declared call count. The separate database-refusal case selects its exact
experimental action without attempting a build. Existing default discovery and
compatibility dispatch policy remain unchanged.

The variant fixture records explicit seed acceptance and retains its new related
observations as partial work requiring independent review. Catalog generation
and the legacy taint hunt use two separately named work references under one
two-call test allowance. A negative case proves that an approved hunt cannot lend
its allowance to a missing model-backed catalog prerequisite: no request or
finding is produced. These execution contracts do not qualify model accuracy
or promote an experimental tool into the supported defaults.

The IaC directory walker now reports a coverage gap for paths without a final
component instead of assuming one exists. Dependency inspection emits its six
existing receipt fields through a typed projection without a serialization
panic. Tests retain the serialized contract, escaped text and maximum byte count.

Registry checks distinguish the curated catalog from exact compatibility
dispatch. They retain the 181-tool historical policy fingerprint and separately
review six investigation additions, bringing the current count to 187. The
readable checks name phase, runtime, effect, authorization, workspace and finding
store requirements. Production dispatch policy and catalog defaults are
unchanged. Operator documentation now describes the experimental proposal tool's
fixed job, allowance and draft-only result.
