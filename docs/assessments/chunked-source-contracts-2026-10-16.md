# Chunked planning, retries and source membership

Shared preparation rejected the chunked scanner's advertised numeric retry
array and its implemented cache switch. Model-free probes also showed an empty
scope file widening to the whole repository and a scope list planning an owned
file outside the selected root. All probe source was inert metadata under
`/tmp`; no provider request or target execution occurred.

## Repairs

Both entry points now declare `failedChunkIds` as JSON, preserving stored and
direct-input comma-separated strings while admitting numeric/string arrays.
The generic settings browser treats this structured retry selection as workflow
input. Supply it through `run` input; existing stored CSV values remain usable.
Empty selections fail instead of expanding work. Unknown IDs fail against the
actual plan. `reuseCachedChunks` is a declared boolean; its compatibility
default remains true. Explicit false requests fresh discovery without granting
calls or approving work. An engine test distinguishes a new scripted opinion
from an earlier cached result without a real model.

Chunked discovery refuses accepted scope/context references, focus and multiple
passes before model work. Standard discovery owns accepted membership and
immutable context. Cache control on standard discovery is refused instead of
ignored. These checks share canonical preparation across interfaces. No model,
runtime or strategy is silently substituted.

Planning reports selected chunk IDs and workload while retaining full geometry
for review. Its receipt states that no scan ran, identifies cache reuse and
names dollar uncertainty. Legacy token bands remain heuristic fields;
`budgetUsd` is an observed-cost stop, and a request can exceed it. Shared
approved call limits remain required. The hidden `full-mode:hunt` alias is
Compatibility and auxiliary, with exact dispatch retained.

Explicit empty scope files, empty source lists and missing explicit `since.txt`
files fail. Only an absent implicit default leaves whole-repository planning
available. Scoped source paths use the existing contained, symlink-free file
adapter. Outside, missing, symlinked and nonregular files fail before discovery.
Absolute contained paths normalize to relative membership.

Planned source windows use bounded reads from the same authorized file handle,
including the first window of a larger file. Unreadable or shortened planned
source raises an error instead of producing an empty prompt. Tests compare
window source and headers with exact owned Unicode slices. No new public Rust
struct fields or versioned artifact formats are introduced.

## Remaining boundaries

This does not qualify chunked precision, accepted context delivery, source
version isolation or complete traversal/resource guarantees. The legacy walker
still has independent traversal, whole-file window planning and omission
behavior. A single file can exceed the approximate grouping target. Late
failure recovery and retained intermediate findings need more evidence.
Standard discovery remains the guided path; chunked accepted context is
unsupported. The primary tool's chunked `dryRun` remains runtime gated; use the
compatibility alias for model-free geometry.

The first native run correctly retained an unsupported scoped request as
`blocked`, with its reason and zero findings in Report. The fixture had wrongly
required no Scan row and a `failed` status. The corrected case distinguishes
blocked work from completed coverage. This was a test-expectation defect.
