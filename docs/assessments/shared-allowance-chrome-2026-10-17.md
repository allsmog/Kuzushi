# Shared investigation allowance in workflow chrome

## Product gap

The retained J121 partial Scan used four of six shared calls, including one
unsettled request, while its wide sidebar displayed session-only zero usage.
Background workers and restarted sessions spend against the durable
investigation ledger, so process-local cost does not explain remaining work.

## Change

Map and Scan bind the read to their displayed attempt. Review follows the
selected Scan, including qualified earlier-source history, rather than a newer
unaccepted attempt. A new read-only Core application helper authenticates each
recorded request and its explicit or inherited allowance, rejects conflicting
investigation identities, and reads the current shared ledger. It does not
load scope artifacts, select unrelated target history, migrate a store, approve
work or reserve requests.

The existing asynchronous hydration workers read this projection at most once
every two seconds. The cache is keyed by the canonical target and exact run
references. The previous read stays visible during refresh. Failed reads
replace it with an unavailable state and remain retryable. Background reads
preserve navigation and the composer draft.

The wide rail shows committed/approved calls, protected Review capacity,
remaining other calls, unsettled requests, qualified dollar accounting and
investigation identity. The footer prioritizes the shared call counter in
narrow terminals. Plain output serializes the same rows. Report remains the
full accounting reader; Replay keeps its separate recorded-request projection.
Targets without a recorded grant retain explicitly labeled session accounting.
Missing ledger data cannot become zero shared usage.

The second frozen run confirmed that repair but stopped with 143 passes and

shared allowance now retains its status row during compact phase reading.
Existing reading modes without an investigation allowance retain their layout.
The projection shares its immutable ledger snapshot across renderers, avoiding
repeated copies of the approved work plan. This second candidate remains
retained separately from the subsequent qualification run.
