# Generated context source identity and returning-workspace notices

Normal model-backed context generation attached an authenticated source hash to
the run result after publishing the immutable context. The document itself had
no content hash. An exact-context read therefore reported source identity as
unknown even when the repository had not changed. The approved context-study
regression reproduces the missing document hash before repair.

The build now carries the host's pre-execution content hash through the common
single, staged and refine publication tail. It replaces provider claims and
inherited hashes before immutable publication. A missing capture removes an
untrusted hash and leaves source identity unknown. This stamp does not create a
grounding verdict, validate context claims or establish complete coverage.

After generation, the shared source-snapshot boundary checks current content.
Source drift retains the original identity and marks the result partial. Errors
retain the captured identity through the existing source-bound failure type.
The focused drift test changes an owned greeting file during an intercepted
runtime response, then verifies historical context, one consumed request and
unchanged global activation. It never executes the source.

Returning-workspace hydration previously synthesized a Git-index change from
any dirty flag in run history or the current repository. That made an unchanged
dirty fixture display `workspace:stale inventory`. A dirty flag cannot prove an
index or content change. Hydration now keeps that uncertainty separate:
`history:check source`, or `source check` in compact chrome. Observed revision,
index and filesystem changes retain the existing stale-state behavior. The
notice is cached, resets on target switch and creates no reindex job.
