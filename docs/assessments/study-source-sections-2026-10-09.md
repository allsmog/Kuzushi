# Study Source views, October 9, 2026

The preparation audit found Source difficult to inspect: repository identity,
engine facts, long qualification and a compact JSON options document were mixed
into one reader. At 40x12, reaching the engine limits required twenty page
advances before the first detail-reader repair. This increment separates the
operator questions while preserving the full recorded data.

## Behavior

Source and context has three views. Overview presents source identity, model,
context binding and explicit omissions. Inputs presents recorded executables,
cache identities and inspection limits. Options presents the complete prepared
input as formatted JSON and the exact supplemental text, when recorded. Tab
and Shift+Tab switch views. The visible footer names the next view and the
read/return controls. Expanded headings name the current view.

Each view retains its form and expanded-reader scroll. Changing views does not
dispatch, revise work, select another context, approve spending or start jobs.
Returning from the reader preserves the selected view and form position. A
retained error owns dismissal and blocks view switching. Cases retain separate
input and executable labels instead of flattening facts across conditions.
Plain form output remains exhaustive across all three Source views; its
selected-section reader emits only the current view.

The static Saved study loaded notice no longer occupies half the narrow reader
on every view. Overview keeps the explanation of source checks and the warning
that a missing observation does not establish a fix. Missing threat-model keys
are labeled legacy selection, distinct from explicit null omission. Malformed
reference shapes and invalid model/revision identifiers are disclosed; display
uses the existing core identifier parsers. Full references remain in Options.
This presentation check does not authenticate context content or replace the
shared dispatch and immutable-context readers.

## Limits

No model or scanner request runs in these experiments. Actual scanner health,
usefulness, every phase/tool outcome, large-case responsiveness, full monorepo
interaction and live-model investigation acceptance remain open. Long absolute
paths and technical options still require inspection; the Options view preserves
compatibility fields without recommending them. Live OAuth recovery and its
approved allowance remain separate. No module maturity or full delivery
milestone is promoted by this increment.
