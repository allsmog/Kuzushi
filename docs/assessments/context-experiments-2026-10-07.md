## Implemented boundary

The declared `campaign:study contextBaselineRunId` option authenticates the
baseline's recorded input, consumed condition receipt, complete engine work and
durable investigation accounting. Planning rejects unchanged context, source
drift, other option/model/runtime/scope/prompt/engine/tool changes, missing or
partial work and a different investigation. Candidate jobs remain finite and
identical. The existing version-1 plan adds optional `contextExperiment`
schema-1 metadata; public plan and study receipt constructors remain compatible.
Approval rereads baseline evidence before admitting the candidate.

The TUI reads the selected baseline's existing allowance through shared prepared
dispatch. A failed read blocks preparation and offers a read-only retry while
retaining the draft and account. Success replaces the failure notice with the
retained commitments and limits. Foreign-target reads, late reads outside the
pending selection and malformed study receipts cannot replace the draft.

Context comparison lists actual candidate jobs. Missing runs remain unavailable;
partial runs retain their status. Enter opens the existing run comparison and
Esc returns to the same selected pass. Comparing changes no decisions or work.
Clearing a comparison invalidates the plan while retaining spending. Selecting
another usage record does not silently replace the context baseline. A context
change withholds historical calibration; unknown dollars remain unknown.
