# Generated boundary context through discovery and Report

Reports previously retained the exact context reference and grounding status but
dropped the source-input receipt attached to a generated boundary revision. The
context reader also showed receipts for explicitly selected files only. An
operator could not carry the accepted file-group provenance through the same
reader and historical investigation export.

The Report application service now projects version-one `scopeContext` and
`fileContext` receipts from the exact immutable context. The additive
`contextEvidence.sourceContext` projection records its own version and identifies
itself as metadata only. It retains source and inherited-context references,
recorded membership, inspection limits, omissions, file hashes and line
references. Captured line text and unknown fields are excluded from this
projection. Malformed and unsupported receipts remain unavailable. Reading a
historical context never selects the globally active revision as a substitute.

The context reader and Report details share a pure receipt presentation. It
separates discovery files from shared context, shows actual supplied excerpts,
preserves literal filenames and labels missing facts as unrecorded. Generated
file groups use their recorded eligible-file count rather than inventing a
requested-file count. Malformed file records are rejected before counting
excerpts. Coverage claims remain recorded claims requiring separate validation.
Report also discloses explicit omission and unbound historical context. Context
reader shortcuts appear only in that reader.
