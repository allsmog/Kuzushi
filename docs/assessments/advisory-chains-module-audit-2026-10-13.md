# Advisory finding relationships and default discovery

`findings:chains` folds recorded confirmed findings into advisory relationships.
It does not inspect source, establish feasibility, generate a reproducer or
complete triage. This audit uses labeled owned metadata only. The existing
classification and ranking implementation is unchanged.

The descriptor previously allowed its receipt to own Review progress. Its
`maxChains` limit is applied after collecting and sorting candidate pairs, so it
does not bound work. The fold also lacks cancellation checks during enumeration.
The default Workbench shortcut invoked that fold directly. Small successful
results do not qualify these resource and product-value gaps for Core discovery.

The tool now has a Labs discovery override and `phase_result=false`. Its module,
exact tool name, options, compatibility aliases and executor remain available.
The default shortcut explains its experimental status without opening the live
fold or starting a worker. An already-open relationship view can still close;
saved scene artifacts remain readable. The shortcut preserves composer text and
cursor. No implementation is deleted or promoted.

The default `persistFindings=false` run preserves all finding rows, raw
observations and human decisions. Opt-in candidate publication is retained but
not functionally qualified by this audit. Optional report output is subject to
the shared state-write path policy. Raw executor calls bypassing preparation are
not a supported interface and receive no containment qualification here.
