# Partial context remains explicit through Map and Report

The published-repository preparation exposed a real workflow limitation:
`context:build` honestly reported bounded content inspection, and importing an
architecture draft then failed because verification required the complete
entry-point set. Large files could therefore prevent even an inactive,
inspectable context draft.

Verification now uses a separate authenticated-observations reader. It retains
current source checks, exact snapshot derivation, catalog validation and the
catalog's own recorded coverage. Consumers that require the complete set still
use the original strict reader. A partial catalog never proves absence outside
its rows and cannot authenticate a complete-catalog receipt.

The verification verdict is at best `partial`, with `groundingSource` set to
`partial-catalog` and the recorded reason in `groundingDegraded`. Missing source
citations, invalid links and undispositioned known observations still fail.
Malformed snapshots remain errors. An evidence failure takes precedence over
the partial-coverage warning supplied to scanners.

Partial imports require `activate=false`. They save an inactive immutable
revision and return a partial run receipt. Existing Map review then requires
explicit acknowledgment before that exact context can guide a scan plan.
Nothing activates another context, adds scan work, grants calls or claims
complete repository coverage.

Report now carries an additive, versioned `contextEvidence` projection from the
exact selected context, including its recorded verification and inventory
receipt when present. Scope studies retain evidence per boundary, and context
matrices retain it per case. The projection shares the existing exact-context
read with operator guidance, preserves unavailable and omitted states, and
never substitutes the active revision. The TUI shows context grounding near the
start of Report, with the recorded limitation under details.
