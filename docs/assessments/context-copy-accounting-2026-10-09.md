# Spending retained through context copies

A checked regeneration copy previously lost its investigation reference when
accepted as Map. The checked revision had a new runtime-free producing run,
so the reader treated it as unbound even though its original synthesis had
already consumed a provider request. A real shared-dispatch integration test
reproduced this gap before the fix.

## Shared recovery behavior

The authenticated Map context reader now resolves accounting through explicit
immutable copy origins when the current run has no allowance reference. It
keeps the selected revision and document unchanged. It never substitutes the
globally active context or trusts budget claims inside document text.

A current run's recorded allowance reference takes precedence. Otherwise the
reader follows `sourceRevisionId` links, authenticates each immutable object,
and checks an origin's producing run and exact revision before recovering its
reference. It follows at most 64 copy links with cycle detection and bounded
store reads. An ordinary predecessor is not a copy origin. Legacy
roots with no recorded accounting remain unbound; malformed or missing known
origins fail explicitly. Known run damage or a result naming another revision
cannot silently become fresh spending.

The existing allowance loader then reads the latest durable investigation
revision. A saved context reference does not transfer work approval. A new
finite plan still requires separate approval, and previous consumption and
protected Review capacity remain intact across that revision and restart.
No module descriptor, public JSON format or execution policy changes.

## Limits and remaining acceptance

The lineage walk is finite and read-only, but it can authenticate up to 64
objects and producing runs. Existing object authentication can reread store
metadata; this is not a single filesystem pass or a total IO/latency ceiling. Longer
copy history produces an explicit error; no history is truncated or repaired
automatically. Exact context objects remain stored independently of spending
recovery. Missing accounting must be restored before implicit continuation.

This fixture has no real commit transition, live synthesis or discovery-quality
evidence. Live enrichment, full investigation/report acceptance, large-history
performance and complete interface/reference-product parity remain open. Tool
qualification stays 55 of 109, with 54 unassigned. All nine broad delivery
milestones remain open. Work stays uncommitted on main.
