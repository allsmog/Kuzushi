# Kuzushi Port Plan

This is the working port plan for shipping Kuzushi as the Rust app while
tracking upstream OpenAI Codex as substrate only.

## Substrate Decision

- Upstream source: https://github.com/openai/codex
- Local tracking: git remote `upstream-codex`
- Strategy: port small substrate changes from upstream into Kuzushi-owned Rust
  boundaries. Do not vendor or subtree whole upstream app files unless a future
  sync requires it and the local patch is documented in `UPSTREAM_CODEX.md`.
- License and notices: keep Kuzushi MIT licensing in `LICENSE`, retain upstream
  Apache-2.0 text in `LICENSES/Apache-2.0.txt`, and record attribution in
  `NOTICE`.

## Product Identity

Kuzushi ships as:

- binary: `kuzushi`
- alias: `kz`
- prompt: `kuzushi>` or `kz>`
- header: `KUZUSHI`
- state directory: `.kuzushi/`

Codex wording is allowed only for upstream provenance, compatibility adapter
names, provider/OAuth implementation details, or dependency names. Public help,
docs, package metadata, and errors should say Kuzushi.

## Artifact Contract

The target run artifact contract lives in
`docs/architecture/kuzushi-artifacts.md`. The current Rust run substrate writes
run metadata, legacy run summaries, events, trace steps, input/result
artifacts, manifests, latest-run lookup, canonical snapshot placeholders,
LLM trace metadata, TUI scan/agent success/failure lifecycle events, and
failure handoff. The run recorder also promotes rich context, attack-surface,
threat-model, recommendation, findings, proof, and Markdown report fields from
tool output into canonical files. Triage, verify, patch, threat-model, and
report producers now return canonical snapshot fields;
remaining work is enrichment for older or deferred producers that do not yet
return those fields. Full-mode hunt/dry-run, variant/ndiff success and
rejection outputs, pipeline gates, smoke next-step, context build, workspace
export, classifier-gate, deep-audit, threat-model read/methodology, router
show, and hidden taint-CWE selection now also use explicit result envelopes
while preserving their structured payloads.
Threat-intel apply/list/harvest, threat-leads build/read, workspace status,
config show, module-recommender, public taint-iris-next report outputs, and
Carlini/offense-review threat-hunt outputs now do the same. The remaining raw
producer audit excludes catalog arrays, internal artifact writers, and
explicitly deferred hidden surfaces; visible residual work is now limited to
deliberately partial/error branches or deeper enrichment. The fast architecture
gate now also checks that the documented canonical artifact filenames stay
referenced by the Rust run/report substrate and regression tests. Machine-
readable schemas now cover `run.json`, `artifacts.json`, `failures.json`,
`events.jsonl`, `trace.jsonl`, and the canonical snapshot files
`context.json`, `attack-surface.json`, `threat-model.json`,
`recommendations.json`, `findings.json`, and `proof.json`; the architecture
gate checks those schema/docs/token contracts, including required
camelCase/snake_case alias groups for run metadata, artifact manifests, and
failure handoff payloads plus constrained route, finding, proof, and
recommendation vocabularies.
Run metadata now fingerprints any
`<target>/.kuzushi/house-rules/*.md` and
`<target>/.kuzushi/prompts/<module>/<verb>.md` files, and the Markdown report
surfaces those digests in the reproducibility section. The same run metadata
records the persisted `<target>/.kuzushi/threat-model.json` digest when that
snapshot exists and captures `KUZUSHI_*` / credential-env influence as hashed
or redacted environment fingerprints. Target git metadata now records the
scanned repository commit, branch, and dirty flag separately from Kuzushi build
git provenance.

## Quality Gate

The quality gate lives in `docs/quality/crap-gate.md`.

Required command:

```bash
pnpm quality:crap-risk
```

All new or modified Kuzushi-owned production code must keep CRAP-risk below 7,
function complexity at or below 4, and function bodies under 40 logical lines.
`pnpm quality:model-safety` also guards the no-silent-model-fallback boundary
by checking for hardcoded provider-model defaults and the Rust enforcement
helpers that require explicit model selection and reject router fallback chains.
`pnpm check:docs` now starts with a port-contract check that keeps the required
plan, upstream, architecture, artifact, and CRAP-gate docs present and wired
into package and CI guardrails. CI no longer ignores Markdown or `docs/**`
changes, so docs-only PRs still exercise the documentation guard. The same
contract check rejects whole tracked Codex subtrees under common vendor,
third-party, and reference roots so upstream remains substrate-only. The
architecture gate also includes a validated-wording check so future
`validated` claims stay confined to proof, verification, patch-validation,
input-validation, or structural regression-gate contexts. Current contributor
and architecture guidance also rejects stale monolithic Rust file paths for
split module, finding, scan, app, and renderer directories.

hidden from the default catalog/recommender path because they are specialist
workflows:

- `systems-hunt`
- `tob`

`systems-hunt` is complete as hidden DAG nodes selected through `sast:scan`;
its `systems-hunt:*` entries are internally registered DAG nodes, not visible
catalog tools. `tob` is complete as a hidden exact-invocation plugin-backed
adapter with explicit plugin-root and runtime/model requirements.
